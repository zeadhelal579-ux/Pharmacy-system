# PharmacyERP — Tech Stack

## الاختيارات

| الجزء | الاختيار | السبب |
|---|---|---|
| الواجهة | React + TypeScript strict + Vite | الواجهة الداخلية محتاجة مكونات مشتركة للـPOS والجداول والنماذج وحالات الأخطاء. TypeScript بيمسك اختلافات عقود البيانات وقت التطوير. |
| التصميم | Tailwind CSS v4 مع @tailwindcss/vite، وCSS مخصص للطباعة | Design tokens للألوان الدلالية والمسافات والتركيز، ومكونات واحدة لكل إجراء متكرر. نختبر دعم v4 على أجهزة الفروع قبل اعتمادها. |
| التنقل والداتا | React Router، TanStack Query، وعميل TypeScript مبني من OpenAPI | الروابط مستقلة لكل شاشة، وفصل حالة السيرفر عن حالة السلة. مفاتيح الكاش تشمل الموقع وتتصفّر عند تغيير الجلسة. |
| Backend | ASP.NET Core .NET 10 LTS، EF Core، OpenAPI | تطوير الكود الحالي كمونوليث منظم حسب المجال. قواعد السعر والمخزون والصلاحيات في السيرفر. |
| قاعدة البيانات | SQL Server ومهاجرات EF Core | نحافظ على توافق البنية الحالية، ونختبر الإنشاء من الصفر وترقية نسخة بيانات منفصلة. ترخيص واستضافة SQL Server يتحددوا قبل الـPilot. |
| المهام الخلفية | Hangfire الموجود | مهام النواقص والصلاحية وإرسال التكاملات عند الحاجة، مع إعادة محاولة آمنة ومراقبة الفشل. |
| الهوية | جلسة متصفح عبر cookie آمنة HttpOnly مع حماية CSRF للـAPI على نفس الـorigin، أو ربط هوية العميل بعد التحقق | جلسات قابلة للإلغاء، وصلاحية لكل إجراء وموقع. تغيير الجلسة الحالي يحتاج ترحيل الواجهة والـAPI مع بعض. |
| الاختبارات | xUnit + SQL Server للاختبارات التكاملية، Vitest وPlaywright للواجهة | نختبر التزامن والمعاملات بقاعدة حقيقية، ومسارات البيع والاستلام وتقفيل الشيفت بالمتصفح والأجهزة الفعلية. |
| التشغيل | Git وCI، بيئة عرض وبيئة Pilot منفصلتين، HTTPS وسجلات منظمة وتنبيهات ونسخ قابلة للاستعادة | نشر قابل للتكرار، فصل البيانات، تتبع الأعطال وربطها برقم العملية. مزود الاستضافة يتحدد بعد قياس الشبكة ومتطلبات العميل. |

الواجهة الحالية Vanilla JS مناسبة لنطاقها الحالي. الانتقال لـReact له تكلفة إعادة بناء الشاشات وتدريب واختبار، ومكسبه في مشاركة المكونات وإدارة حالات تدفقات التشغيل الجديدة. Vite مناسب لواجهة داخلية بتستهلك API موجود، وصفحات التسويق لو اتطلبت ممكن تكون مشروع مستقل. منطق العمل بيتراجع في C# قبل ربط كل شاشة. [React مع Vite](https://react.dev/learn/build-a-react-app-from-scratch) · [تثبيت Tailwind مع Vite](https://tailwindcss.com/docs/installation/using-vite) · [متطلبات متصفحات Tailwind v4](https://tailwindcss.com/docs/upgrade-guide#browser-requirements) · [.NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)

## تنظيم الواجهة المقترح

- `front-end/pharmacy-web/src/app` للمسارات والجلسة وتهيئة التطبيق.
- `src/features` لمجالات POS والمخزون والمشتريات والتحويلات والإدارة والتقارير.
- `src/shared/ui` للمكونات و`src/shared/api` للعقود والعميل و`src/shared/i18n` للعربي والإنجليزي.
- ندعم RTL باستخدام خصائص Tailwind المنطقية، ونثبت اتجاه الباركود والأكواد داخل النص العربي. نراجع لوحة المفاتيح والتباين وحالات الانتظار والخطأ قبل اعتماد المكونات. [Tailwind logical properties](https://tailwindcss.com/docs/top-right-bottom-left#using-logical-properties)

قارئ USB وطابعة الإيصالات يتم اختيار مسارهم بعد تجربة موديلات الفرع. التكامل الضريبي يُضاف حسب المتطلبات اللي يؤكدها العميل والمحاسب. مفيش اعتماد على AI في دورة التشغيل الأساسية.
