# PharmacyERP

PharmacyERP نظام لإدارة صيدلية متعددة الفروع ومخزن مركزي. المخزون بيتتبع كل دفعة برقمها وصلاحيتها في كل موقع. البيع والتحويل والاستلام والجرد بيسجلوا حركات، فمدير الفرع يقدر يطابق الرصيد مع اللي حصل فعليًا.

## سير الشغل

1. **المشتريات والمخزون.** الموظف ينشئ أمر شراء لمورد، والمدير يعتمده. الاستلام ممكن يتم على أجزاء، وكل استلام بيحفظ رقم الدفعة والصلاحية والكمية وتكلفة الوحدة. فيه معاينة لاستيراد الرصيد الافتتاحي وجرد بالدفعة وتسوية بالاعتماد.
2. **التحويل.** الوجهة تطلب تحويل من موقع تاني. مسؤول المصدر يعتمد ويحجز الرصيد، وبعد الشحن الكمية تظهر قيد النقل. الوجهة تسجل الصالح والتالف والعجز، وتقدر تستلم على مراحل.
3. **البيع.** الكاشير يفتح شيفت ويبحث بالاسم أو يمسح الباركود. البيع ممكن بالشريط والعلبة من نفس رصيد وحدات الأساس. السيرفر بيحسب السعر وبيخصم من أقرب صلاحية متاحة أولًا (FEFO). الإيصال بيتحفظ في قاعدة البيانات وينفع تعيد طباعته. الخصم فوق الحد يحتاج اعتماد، وإعادة إرسال نفس عملية البيع ترجع نفس الفاتورة.
4. **المراجعة.** مدير الفرع يراجع النواقص والصلاحيات والفواتير والمرتجعات والمطابقة. مدير النظام يقدر يتابع الفروع ويفتح قرار سحب لدفعة. الدفعات المعزولة والمنتهية والمشمولة بقرار سحب مفتوح بتخرج من المتاح للبيع.

## الأدوار

| الدور | شغل الدور |
|---|---|
| مدير النظام | إدارة المستخدمين والمواقع المتاحة له ومراجعة التقارير وقرارات السحب |
| مدير الفرع | متابعة الفرع والمطابقة واعتماد الجرد والخصومات والمشتريات |
| الكاشير | البيع وفتح وإقفال الشيفت والفواتير ومرتجع البيع |
| مسؤول المخزن | الاستلام والمخزون والجرد والتحويلات وعزل الدفعات حسب صلاحيات الموقع |

## التشغيل المحلي

شغّل الباك من فرع `back-end` باستخدام .NET 10 وSQL Server، وبعدها شغّل فرع `front-end` باستخدام Node.js 24. الـAPI المحلي على `127.0.0.1:5277` والواجهة على `127.0.0.1:5173`. Vite بيمرر طلبات `/api` و`/health` للباك. خطوات الإعداد في README كل فرع.

## ديمو Vercel

فرع النشر هو **`front-Deploy`**. في Vercel اختاره كـ **Production Branch** وسيب **Root Directory** على جذر الفرع. إعدادات Vite والبناء موجودة في `vercel.json`. الديمو فيه دخول بضغطة واحدة وبيانات فرعين ومخزن، وبيشتغل بالكامل داخل المتصفح.

## نطاق التشغيل

تسجيل مدفوعات البطاقة والمرتجع جزء من المطابقة. حركة الدفع نفسها تتم على جهاز الطرف الثالث. اختبارات التشغيل هنا محلية ببيانات تجريبية. تشغيل فرع فعلي محتاج إعداد استضافة ونسخ احتياطي وقياس حمل ومراجعة أجهزة الفرع والتكاملات المطلوبة.
